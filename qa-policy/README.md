## 处理流程

1. `knowledge-scope.mjs` 共用实体别名、地点边界和范围校验。未知名称仍拒答，不把西教、北教、东七或图书馆套入已知行程。普通动词、口语和助词不再逐词拦截；“收到/提到/撤回”中的到/回不作为地点方向。
2. 两端 Dify 输入先规范地点名称，`originalQuestion` 保留原文，`question` 使用现有端点名称；同轮 `knowledgePolicy` 版本为 `campus-known-scope-v2`，提供全部别名与边界。仅本地提示词及管理员镜像更新，本轮没有发布学校工作室系统提示词。运行时规范化和后端检查已经生效，学校 API 真实联调通过。
3. 已知问题缺少必要输入时继续澄清：未说明上课时刻时询问时刻；未给出明确控制值时询问目标，不猜数值。师生同一会话、同一页面行程下可直接补充“八点钟”。上下文五分钟到期、最多一百条，不跨会话或行程继承；只用于补充课堂时刻。异步轮询仍为十秒，预测仍在独立 Worker 中运行。
4. 明确提到的已知出发地/目的地可解析双向行程，返回本次实际使用的行程，避免已知别名因与默认选择不同而误拒答；多个冲突目的地先澄清。简称确认（如“东教就是东教学楼”）本地确认映射，不调用模型、不生成空路线卡，也不接纳未知地点的临时更名指令。
5. 未知实体、缺少事实数据或超出范围时保留精确拒答：**受限于数据，我暂时无法回答这个问题**。这与可澄清的输入不足分开处理。网络、认证、格式错误显示实际故障原因。
6. 原有权限、CSRF、控制白名单、版本核验、待确认方案、撤回、真实执行回执、共享沙盘及问卷/预测模型保持。
