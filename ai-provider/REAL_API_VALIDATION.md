## 已通过

- 官方模型列表接口验证成功，所配`deepseek-flash`可用。配置文件由用户自行填写；密钥仅由后端读取并发往官方授权头，没有显示、记录到验收证据或加入Git。
- 师生真实API：紫云→东三的省时问题、云峰→东教的距离问题，均返回`provider=deepseek`且通过原路线与数值校验。接口样本分别约721毫秒和782毫秒，代表本机当次样本，不承诺稳定延迟。
- 浏览器师生页真实提交两类问题，页面正确显示“AI出行建议”、三路线估算时间与距离，未知地点由本地边界规则拒答。普通快答仍可走本地计算，不会把所有成功请求误算为模型调用。
- 管理员真实提示词先在冻结的独立内存副本检验：解释当前认知/意愿/触达因素，提出待确认方案，确认执行与撤回后参数一致；两次模型调用约2063毫秒和2036毫秒，没有触发格式修复重试。
- 用户自行设置并登录独立测试管理员。网页实际发送分析和优化问题，助手明确说明参考了路线认知、尝试意愿和引导触达；建议未自动执行。
- 网页确认方案后，测试版引导覆盖从0%调到60%，配时从自动调控切到固定配时。师生端再次真实提问，返回的runId和完整settings与该测试沙盘一致（约651毫秒）。
- 网页撤回后，引导覆盖回到0%、配时恢复自动调控，随后恢复测试沙盘4倍播放。依据原模型，已经送达的路线信息不会被撤回覆盖设置抹除；因此只恢复了参数，不声称逐车状态完全回到调参前。未触碰正式沙盘。
- 浏览器实际完成早八完整出发推演：在本次360人固定种子场景，建议07:43前出发、北侧环岛线、预计07:53到达，约9.3分钟。Worker实际计算70038毫秒；同条件缓存复用请求约54毫秒。只是当前模型样本，不是每日固定建议或实测交通结果。该计算由项目Worker完成，不调用DeepSeek。
