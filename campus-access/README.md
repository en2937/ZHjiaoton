# 校园网演示入口

只在本机校园网 `10.x` IPv4 地址的 TCP 4180 端口提供入口，不需要域名或外网穿透。实际跨设备访问取决于校园网的设备隔离和网段路由，不能仅凭本机测试保证全校可访问。

## 启动与访问

1. 双击根目录的 `启动校园网访问.cmd`。它会复用已经运行的沙盘/问答服务；若服务没有运行，使用原项目启动脚本启动。
2. 如 Windows 防火墙尚未放行，以管理员身份运行根目录的 `允许校园网访问.cmd`。规则只允许 `10.0.0.0/8` 来源访问当前校园网 IPv4 的 TCP 4180，不开放其它端口，不关闭防火墙。
3. 把启动脚本输出的网址发给另一台连接校园网的设备。沙盘是 `http://校园网IPv4:4180/`，AI 问答是 `http://校园网IPv4:4180/student/`。
4. 校园网地址可能在重新联网后变化。变化后停止入口并重新启动、更新防火墙规则，然后分享新的地址。

电脑须保持开机、不休眠，校园网及两个项目服务持续运行。锁屏可继续提供服务。

## 当前权限

- 师生：查看同一份沙盘状态、缩放和平移地图、导出当前模拟状态，以及 AI 问答。
- 管理员：本机登录入口 `http://127.0.0.1:4174/login`，校园网管理入口 `https://校园网IPv4:4190/login`。首次账号由服务器拥有者在本机设置。HTTP 4180 保持只读；安装本项目证书后，可通过独立 HTTPS 入口登录管理。详见 `admin-access/README.md`。
- 学校 Dify 密钥仍由原本机后端读取，入口仅开放师生相关页面和 API；不开放配置、旧人工样例接口和内部文件。
- AI 提问入口每个来源地址每分钟最多 8 次，最多同时处理 4 条问题，以保护演示额度。问答服务现有内存会话上限仍为 100；长期运营需要进一步处理会话回收。
- 网关会先校验校园网来源、Host 与 Origin，再转发到原本机服务；不更改原有服务的监听范围和同源校验。

## 停止与恢复

双击 `停止校园网访问.cmd` 停止师生校园网入口和新增的管理员入口，原沙盘及问答服务继续运行。以管理员身份运行可同时删除本端口的演示防火墙规则；普通权限停止时会保留该窄范围规则，但入口关闭后不再提供访问。

管理员登录更新后，原仿真引擎和问答程序未修改；沙盘服务增加服务端控制权限，师生网关读取只读页面。项目记录修改前副本：`_backup/20261013-151744-before-campus-access/AGENT.md`。

## 验收

运行 `node --test campus-access/tests/gateway.test.mjs` 验证来源/同源拦截、实际共享状态、只读策略、两端跳转、资源白名单、压缩、限流、请求大小及上游中断。Windows 本地网络测试需允许本地监听。

跨设备检查：另一台校园网设备打开两端页面，确认地图与 AI 提问可用；本机调整绕行比例后，观察师生页更新；尝试策略操作应不可用。若同 Wi-Fi 也无法连接，检查防火墙和无线客户端隔离；同 Wi-Fi 可用但其它楼宇不可用，需学校网络管理方确认路由/访问策略。不要擅自关闭校园网络的隔离设置。
