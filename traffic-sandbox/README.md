# 紫金港校园交通沙盘 · 本地原型 0.10

车辆从地图标注的 1、2 两处及藕舫中路北侧进入，在两个主要路口选择直行、左转或右转，沿支路驶出地图边界后消失。电动车为蓝点，自行车为紫点，机动车为较大的红点。

迪臣中路按方向使用两条分离道路，三种车型均南行走西侧、北行走东侧；两端路口共同接入点保持连续，往西北离场沿东侧道路延伸，往西南离场沿西侧道路延伸。网页显示两条浅蓝轨迹。藕舫中路西侧道路供电动车、自行车双向通行，东侧道路供机动车双向通行。东北出场路线沿道路北上，已修正原先穿过水面的斜线。机动车在藕舫南路两个方向仍走东侧道路。两侧道路分别跟车，机动车不会隔着道路跟随骑行车辆。现已增加道路模拟扩宽、横向空间占用与平滑变道超车；路口仍有减速、停车、橙色队列提示、等待时间与有序放行。

底图已替换为项目根目录最新的 Map.png。新图上半圆形环岛成为 1、2 之间的备选路线：环岛南侧由西向东、北侧弧线由东向西，组成逆时针环流。按最新红线标注，新增出发点 1 附近经文化广场北侧、东侧道路接入环岛的双向连接线；从该入口进环岛后先沿西半弧，再走南侧前往 2，返程经东半弧驶出北侧入口。原有主路仍可选择。环岛路线和主路在接入点共用路段，车辆不会在接入处跳跃。

## 启动

双击“启动沙盘.cmd”，保持终端窗口打开，访问 http://127.0.0.1:4173/ 。已安装 Node.js 20+ 时也可执行 `node server.mjs`，无需安装 npm 依赖。

## 新增功能

- A 西侧路口增加可见红、黄、绿灯，南向与西向互斥放行。自动模式按队列、车型占用、等待时间和下游空位分配绿灯；最低 20 秒、有对向需求时最高 60 秒，黄灯 3 秒、全红 2 秒。无对向近期需求时可保留当前绿灯。
- 页面顶部侧栏可选择“自动调控”或“固定配时”（每方向 30 秒绿灯，同样的黄灯与全红）。切换保留安全过渡；统计自重置开始累积。对比时分别选模式并重置，在相同需求与相同模拟时长下观察。
- 点击“观察 A”放大查看灯色、停止线与队列；面板显示调整原因、A 时间平均排队和已通过车辆的平均路口等待。倒计时会动态调整。

- 每个方向三格横向空间：机动车占两格，非机动车占一格。混行路段可一辆机动车与一辆非机动车并排，或三辆非机动车并排；两辆机动车不能并排占用同一方向的三格空间。
- 较快车辆遇慢车且相邻位置有安全前后间距时变道，过渡期间同时预留两侧空间。完成超过后统计一次超车，条件允许时返回原位置。
- 点击“并排 / 超车示例”会切换到迪臣中路预置观察场景，自动放大并采用 1×，展示三车并排、机动车与非机动车并排、慢自行车被电动车超越。示例不新增入场车辆；重置返回普通推演。
- 青色描边表示变道，完成超车后短暂绿色描边；右侧显示变道及完成超车次数。路段端部收束、路口附近禁变道，等待线仍生效。

- 两个路口的三向选择，以及 1 ⇄ 2 之间的逆时针环岛备选路线和北侧入场路径，共十七条出场路径。
- 新增北侧入场车流，默认 8 辆/分钟，可调 0–20；包括骑行与机动车，车型比例参照其它需求参数。设为零停止生成北侧新车；重置可清除预置北侧车流。北侧进入后可直行向南、右转向西或左转向东。
- 六个地图边界出口：西北、西南、西、东北、东、东南。
- “环岛及支路分流”默认 40%，范围 0–80%；环岛车流约占1、2 两处新车的设定比例一半（默认 20%）。其中一半环岛车流走新增北侧连接线（默认 1、2 两处新车的 10%），另一半走原环岛路线。调整只影响后续入场车辆。
- 按实际所在道路跟车、等待；分流后车辆在不同道路上独立运行。
- 路口观察区统计实际发生的左转、直行、右转次数。
- 离场数记录驶出地图的所有车辆；平均离场耗时只统计新进入、完成离场的车辆。
- 平移或缩放只是查看视角，车辆离场依据始终是原始地图边界。

## 0.11 共享沙盘与 C 端

运行项目根目录的“启动项目.cmd”，之后打开沙盘 http://127.0.0.1:4173/ 与 C 端 http://127.0.0.1:4183/student/。服务只监听本机。服务端拥有唯一 Simulation；页面读取 /api/simulation，所有参数、暂停、速度、重置和展示操作经 /api/control 生效。多个页面读取同一状态；浏览器不再各自推进时间。关闭网页不暂停服务器，暂停请用播放按钮。服务重启从初始状态开始，尚无跨服务重启保存。

C 端后端每轮请求读取本轮共享状态，比较 1↔2 的主路、原环岛和北侧环岛线。路程按用户提供的主路1→2约1200米进行近似比例换算；不是实测测绘。返程旅程连接回地图标注的1点，去程终止于2点，不包含地图外离场段。

时间为路线自由流时间加当前信号等待与队列服务时间的规则估计，属于当前快照的比较值；不是既有全网平均离场时间，也不是训练模型预测。步行、超车展示场景和未来出发时段无相应数据时明确提示。没有自动回退到人工样例。

新增实现：shared-simulation.mjs、student-data.mjs、dist/shared-client.mjs。沙盘原交通规则和仿真内核未变。Dify 密钥仍只由 dify-integration-lab 后端加载。

## 0.12 北侧环岛独立绕行 A

页面移除“环岛及支路分流”，改为“北侧环岛绕行 A”，范围0–100%，默认60%。该比例直接作用于能绕行、且原路线经过A的车流；普通环岛和其它支路采用固定基础选路权重。发往西出口/西南出口等不能通过现有北侧线路绕开A的车辆保持原目的地，北侧边界入场仍独立，不会因为滑块100%让所有车辆消失。

新增1-bypass-east与1-bypass-north，使来自1、去东/东北出口的车辆也可绕A并保留出口；全路网十九条出场路径。所有环岛路段逆时针，机动车道路规则继续执行。

修改比例后，尚未经过路线分岔点的在场与入口等待车辆根据原始选路随机数安全改道，坐标、进度、车型与目的地不变；已经驶过分岔点的车继续原路。面板显示已选北侧线路车数、安全改道次数和A当前队列。C端仍读取同一个服务状态。

25项仿真与22项接口检查通过。tests/bypass-comparison.mjs可重现两场景各600秒的关闭/60%对比，结果在bypass-comparison.json。默认高峰A平均排队30.33→5.52辆（下降81.8%），平均等待47.15→18.09秒（下降61.6%）；南向偏重高峰A平均排队33.30→7.17辆（下降78.5%）。同时B平均排队增加，不能称为全网所有指标均改善。

以上为合成规则仿真、0.12模型内对比，不是实测结果或与旧版本的直接对比。旧signal-comparison.json保留为0.10历史记录，旧模型在历史备份中；当前signal-comparison.mjs使用0.12规则和默认绕行60%，不能用于重现0.10数值。手工比较时保持同一需求、种子、模拟时长，并各自重置。
