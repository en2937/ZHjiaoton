# C端沙盘数据接入验收

日期：2026年10月13日。沙盘版本0.11，页面标识“本地原型 / 11”。

## 已完成

- 沙盘服务端拥有唯一 Simulation。网页不再独立推进仿真；参数、速度、暂停、重置和超车展示经同源 API 生效。
- C端每轮读取共享沙盘状态，按当前行程和车型比较主路、环岛、北侧环岛线。网页每3秒刷新连接与排队状态；旧回答带快照时间，参数或重置变化提示重新提问。
- 每次 Dify 请求带本轮路线、灯色、队列、参数、指标和状态版本；后端核对模型路线，卡片数字来自沙盘适配层。断线明确失败，不回退到人工样例。
- 用户提供地点1到2约1.2公里。本轮按主路1→2约1200米作近似标定，其余路径按地图长度比例换算。往返均终止于地图标注地点，排除地图外离场段。
- 增加项目根目录“启动项目.cmd”，同时启动沙盘与C端；Windows PowerShell一键入口检查通过。

## 检查结果

- 原有24项仿真测试通过；21项后端/接口测试通过，包含7项新增共享状态测试。首次沙箱中的本机网络测试受EACCES限制，获准本机测试后通过；时间断言采用浮点容差。
- 新增测试覆盖双视图同状态、暂停与重置、每轮最新数据、队列和灯色对估计的影响、绕过A、步行/未来/展示缺数据、断线无样例回退、双向旅程连贯和跨站拒绝。
- 学校真实API两轮通过：1→2电动车省时，三条路线为283/302/267模拟秒与约1200/1290/1320米，选择北侧环岛线；2→1自行车近路，三条路线为324/377/297模拟秒与约1200/1410/1190米，选择北侧环岛线。数值对应当次快照，不是固定结果。
- 部署后暂停、改变骑行需求44与分流60及固定配时：C端和沙盘版本一致、参数一致，Dify采用相同版本和路线数据返回建议。未来出发问题仍由本地明确提示缺数据，不调用模型。随后恢复默认设置并重置推演。
- 部署的页面、脚本、样式与地图返回HTTP200；19个程序/说明/启动文件与暂存副本复制后哈希一致。密钥配置未更改或复制。
- 证据：evidence/sandbox-school-validation.json、evidence/sandbox-deployed-validation.json。

## 适用范围

用时为路线自由流时间加当前信号等待和队列服务时间的规则估计，未预测车辆抵达各路口时的未来状态。它不同于原沙盘“全网平均离场耗时”，未接入机器学习或实测标定。距离来源为用户给出的约数。步行尚未建模，超车展示场景不提供普通行程比较。

服务端在浏览器关闭或隐藏后继续推演；暂停应使用沙盘播放按钮。服务重启从初始状态开始，尚未持久化运行状态。正式账号、多人授权及公网部署不在本次范围。

本轮学校管理页面读取超时，未改动发布提示词；实际API验证了现有campus-student-v1协议可以接受新沙盘的三条路线。未进行本轮浏览器视觉或点击验收，不把HTTP和接口验证等同于视觉验收。
