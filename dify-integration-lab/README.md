## 使用

1. 在 https://dify.zju.edu.cn/apps 新建专用 Chatflow，名称“校园交通-独立接入测试”。用 DIFY_SYSTEM_PROMPT.md 配置开始 → LLM → Answer，选择学校可用模型，运行测试后发布。
2. 从该应用的 API 页面取得实际 API 基础地址和应用密钥。运行“配置Dify.cmd”，在本机隐藏输入密钥。配置保存为 .env.local（JSON 格式，本目录 .gitignore 已忽略）。不要把密钥发到聊天里。
3. 运行“启动接入测试.cmd”，访问 http://127.0.0.1:4183/。先检查连接，再在同一会话中分别选择 A/B 发送相同问题。
4. 观察回答是否明确使用 fixture-A / fixture-B，分别引用 A（主路300、环岛180）和 B（主路160、环岛260）的模拟秒数，建议是否变化。

这些值全部为人工构造接口样例，不是现有沙盘的推演结果，不可用来宣称策略效果。界面会明确标注这一点。尚未接入沙盘共享状态、正式登录或公网部署。

学校应用 API 页面已确认基础地址为 https://dify-api.zju.edu.cn/v1（与工作室域名不同）。模型和权限以实际应用页面为准。学校需要校园网/VPN 时，先确保本机可以访问。

## 行为

- API 密钥只由后端加载，不进入网页源码、状态接口、调用日志或回答。
- 每轮 query 均带最新样例状态，不依赖会话首次 inputs 更新。
- 后端使用流式 Dify 请求并收集完整回答；连接中断、未配置、权限失败和未知状态均明确报错，不伪造答案。
- 人工样例没有未来推演；包含明确未来时段的提问由后端先给出缺数据提示。页面标为“后端数据检查”，不冒充 Dify 回答。此检查是本次实际模型测试暴露“将当前数字当未来耗时”后加入的限制。
- 单个浏览器会话由后端分配匿名 user，并保存自己的 Dify conversation_id。
- 静态资源使用明确白名单，私有配置无法通过 HTTP 获取。
- 限制本机 Host 和同源 Origin；只适用于本机联调。
