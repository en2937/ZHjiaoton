# 上课出发时间推演

## 使用

打开师生页面，选择出发地、目的地、电动车或自行车，问“我想去东教上早八，我几点出发最好？”。也支持“10:00上课，几点出发？”、“下午两点上课，何时出发？”。未提供时刻先澄清。第一版只支持地图已有的1⇄2骑行旅程；没有步行或任意教学楼数据。

默认目标：**预计提前5分钟到达，并在此条件下尽量晚出发**。明确说“避开拥堵、错峰、不想被堵”等时改为：先比较等待与慢行耗时，接近最低（15秒内）的候选优先晚出发，同一时刻优先更低耗时。仍必须预计提前5分钟到。返回用时、路线及估算距离；避堵另给最晚可行方案的对照。预计到达向上取整到分钟，实际判断使用未取整的秒数。停车、进楼、找教室未单独计算。

## 时间与场景

- 从所问课堂前一小时重新构建独立仿真，例如早八使用07:00–08:00。不是将管理员已运行数小时的状态倒带，也不是实时路况预报。
- 使用当前九项设置、初始种子、既有总人数、出发种子和出发曲线模型；推演采用仿真模式和认知与意愿分组，其余参数沿用当前设置。固定需求模式的正式沙盘不切换。
- 学生出发采用已实现的问卷平滑曲线。36份自报调查不等于校园交通总量，原始问卷类别比例也不等于平滑后逐分钟比例。总人数沿用已有模型设定，不从这句提问推断全校人数。
- 用户确认预测模板“早八较集中、十点较分散”，只在计算依据中小字注明假设。08:00采用集中系数0.8、10:00分散系数1.2，其他时刻参考系数1。系数、40分钟中心点和形状不是问卷事实；没有分时问卷，也不改变总人数。
- 以上分时模板只应用于独立预测沙盘，不切换或改写管理员当前运行曲线。机动车、北侧等背景需求沿用当前设置，未凭空给不同时段编造交通总量。
- 未接入真实课表、日期、天气或实测车速；“东教”对应东教学楼的地图标记点，不能推断已抵达具体教室。

### 分时函数

以合并问卷的既有平滑函数为参考。设课前一小时的相对分钟为t，x=t/60、c=2/3、s为上述系数、k=(s−1)/(c(1−c))。采用平滑单调变换w(x)=x+kx(1−x)(x−c)，将每个原计划时刻t映射到60w(x)。

0、40、60分钟固定，局部宽度系数为s；当前系数下导数始终为正。对应密度为f_s(60w(x))=f_0(60x)/w'(x)，积分不变。固定种子和原事件ID不变，严格保留N人，不是把36份问卷当全部人数。原参考类别人数仅作来源追溯，不再声称变换后的实际出发仍严格满足原类别比例。

## 求解

1. 使用正式引擎的0.1秒步长，后台无绘制地推进课前背景车流，保存分钟快照。
2. 以最短路线名义自由行驶用时作不可能更晚的理论上界，从晚向前逐分钟检验三条合法路线，不假设拥堵随出发时刻单调变化，不用二分法跳过分钟。
3. 每次从该分钟快照深拷贝，加入一辆按推荐路线行驶的代表骑行者，排在已有入口队列之后。使用与现有师生估算一致的名义速度（电动车8.4、自行车6.8地图单位/秒），信号、跟车、变道和入口阻塞均由引擎计算。
4. 不让试行车辆生成消耗背景交通的随机序列。保留目的地，抵达地点标记结束，不要求绕到地图出口。
5. 默认最晚出发：找到最晚可行分钟后停止，同分钟按快照用时估计或长度优先检验；不保证该分钟内最快。
6. 避堵：保留最晚可行方案作对照，在0、10、20、30、40、50分钟等有效时刻检验三条路线，再在初选时刻前后5分钟细化。候选固定、种子固定，不按机器运行快慢截断候选后冒充最优。比较“实际用时−名义自由行驶用时”，其中包含入口、红灯、队列和慢行，不能把它全称为车辆拥堵排队时间。在固定候选内选接近最少的较晚方案，不保证连续时间全局最优。
7. 试行中若剩余路程即使按最大速度行驶也赶不上截止时刻，提前结束这个不可行候选。该严格下界不改变可行结果或引擎0.1秒步长。无解与计算超时均明确失败，不编造差异或改善幅度。

这是单种子、抽样时刻、代表骑行者的条件推演，不是准时保证、真实交通预测准确率或已验证收益。不同曲线也可能碰巧得到相同分钟建议，不能强迫输出不同时间。

## 隔离与协议

- `/api/student/chat`新增本地预测分支，解析时刻后由后端计算，不让Dify生成出发时间数字。普通路线问答仍使用原学校Dify协议。
- 网页携带`forecastAsync:true`，短请求返回202和`jobId`，每10秒以同接口轮询（适配现有校园网每分钟8次提问限制，不提高限额）；完成返回200和`kind:departure_forecast`、`provider:sandbox-forecast`。无需新增校园网路由或更改Dify提示词。
- Worker只接收参数和种子，不持有SharedSimulation、管理员控制密钥或状态写入通道。单任务、同键合并、最多8条5分钟缓存；硬时限180秒、内存256MB。失败短暂缓存30秒防止重复计算。
- 运行标识、配置版本、完整设置、场景种子、求解目标、分时模板及模型版本class-replay-rider-v2进入指纹。避堵不得命中同一课堂的最晚出发缓存。轮询时配置变化或完成前再次读取发现变化，返回409。时钟自然推进不会使重建场景失效。
- `ForecastSimulation`仅在Worker内为入口前车查询建立索引，保留原数组位置相同的排序语义；不改正式引擎或仿真步长。混合固定/问卷场景逐字段比对测试约束其一致性。引擎升级后必须重跑该检查。
- 正式管理员服务、权限、CSRF、方案确认/撤回、管理员AI、共享状态和沙盘进程均无需修改或重启。部署只重启师生服务，会清空其内存对话会话；不会改管理员登录会话。
