# 师生端快答与高峰保护

2026-10-18。范围：师生端与旧联调 API、校园网网关。管理员应用和仿真模型未改。

## 回答路径

以下表达只去除首尾空白和末尾句号/问号/叹号后完整匹配：

- 省时：`哪条路更快`、`哪条路时间最短`、`我赶时间，帮我选一条路`。
- 近路：`哪条路更近`、`哪条路距离更短`。
- 当前选择：`按当前偏好推荐路线`。

快答使用当前沙盘规则估算，来源为 `local-routing`，页面标注“本地路线计算”，不会调用 Dify。距离、用时依旧不是实测或未来预测。其他表达交给学校 AI，不能用关键词匹配丢掉否定、目的地或附加条件。没有 Dify 配置时快答仍可用。

AI 每轮为独立请求，不再传 `conversation_id`。输入只含行程、精简路线和数据限制；返回仍必须通过 JSON、路线 ID 和比较维度校验。AI 完成后重新读取状态：普通车流变化按新数据重算；运行场景或策略配置变化则返回 `state_changed`，要求重新查询。不跨用户缓存回答，不共享聊天历史。

## 运行配置

下表是师生服务启动前可设置的环境变量；默认值均可通过 `createLabServer` 的 `policy` 参数注入以便离线测试。环境变量不包含凭据。

| 环境变量 | 默认值 | 含义 |
|---|---:|---|
| `STUDENT_LOCAL_ROUTING` | `true` | 本地快答开关，回退时可设 `false` |
| `STUDENT_AI_CONCURRENCY` | `2` | 当前服务进程的学校模型并发 |
| `STUDENT_AI_QUEUE_LIMIT` | `6` | 最大等待队列，允许设为 0 |
| `STUDENT_QUEUE_TIMEOUT_MS` | `2000` | 排队上限 |
| `STUDENT_AI_TIMEOUT_MS` | `8000` | 取配置、连接、完整读取模型响应的上限 |
| `STUDENT_TOTAL_TIMEOUT_MS` | `12000` | 包含取数、排队和最终复核的总上限 |
| `STUDENT_SESSION_IDLE_MS` | `1800000` | 空闲会话回收时间，活跃会话不回收 |
| `STUDENT_SESSION_LIMIT` | `1000` | 全进程会话上限 |
| `STUDENT_SESSION_RATE_LIMIT` | `8` | 每会话每分钟提问次数 |
| `STUDENT_AI_COOLDOWN_MS` | `30000` | 学校限流或连续超时后的冷却时间 |

多实例部署不共享上述限制；本版针对单台机器、单个师生服务进程。改变截止时间时也应同步调整前端 13 秒兜底；本版验收以默认 12 秒为准。

校园网入口默认最多 32 个在途提问、每 IP 每分钟 60 次；来源、Host、访问范围与请求体限制保留。共享出口 IP 下限流是粗粒度负载保护，匿名会话 ID 也不是认证身份。网关把 `Retry-After` 和请求 ID 转交页面。

状态轮询最多共享 500 毫秒快照；进行中的读取可合并，单个调用者取消不会影响其余调用者，最后一个取消会终止上游。转换缓存最多 64 项；提问绕过已保存快照；读取失败不返回旧数据。页面只在可见时以 5–6 秒随机间隔轮询，恢复可见立即读取。

## 接口和用户反馈

`POST /api/student/chat` 的输入和原有路线字段不变，新增：

- `provider: local-routing`：确定性快答；`school-dify`：已校验的学校 AI 结果。
- `requestId`、`timings`、`latencyMs`；响应头 `X-Request-ID`。
- `timings` 包含 `stateMs`、`queueMs`、`modelFirstByteMs`、`modelMs`、`totalMs`。首包耗时是接收首个响应体分片的时间，不等于学校平台内部纯推理耗时。
- `ai_busy`、`ai_queue_timeout`、`ai_timeout`、`ai_cooldown`、`request_timeout`、`state_changed`、`rate_limited` 等错误码；可重试的容量限制带 `Retry-After`。

服务命令行输出一条匿名 JSON 指标/请求，包含路径、来源、阶段耗时、错误码和队列计数，不含原始问题、输入、Cookie、会话 ID 或密钥。快答命中率按 `provider=local-routing` 占师生请求比例计算；应同时区分有效请求和错误请求。返回指标不意味着模型实际已停止。

页面可取消提问、创建新对话，并隔离旧响应。失败保留原问题；仅显式点击“按当前偏好查看本地路线”才发起本地替代查询。不会自动重试，也不会把复杂问题失败伪装成本地已回答。等待 3 秒后显示剩余上限，不显示虚构排队位置。

模型超时/断开时取消本地读取；取得 `task_id` 时，使用相同匿名用户向 Dify 停止接口发起最多 1 秒的尽力请求。学校部署的支持情况未验证，远端推理可能继续；不会自动重试放大消耗。

## 学校 Dify 手工配置与发布

代码更新不等于学校应用已更新。本轮不登录学校平台、不读取密钥，也未调用真实学校模型。

操作者先导出/记录师生应用当前版本，再在单独测试版本中：

1. 保留“开始 → 单个 LLM → 回复”的结构化路线判断，使用当前 `DIFY_STUDENT_PROMPT.txt`。
2. 关闭历史记忆、不必要检索和工具步骤；模型支持时关闭额外深度推理，最大输出先设为 160 tokens。不能确认模型能力时保留其原设置并记录。
3. 用明确时间/距离、否定、未知目的地和未来问题做回归；部署后用单请求、2 并发、慢问题做小规模对照。
4. 根据错误率、排队率和首包/总耗时决定是否提高并发，不把 API 限流当成模型推理性能。

指代不完整（如“那条呢”）没有历史可供推断：提示词要求返回缺少信息，页面提示用户补全行程或条件。不要启用隐式跨轮事实记忆。
